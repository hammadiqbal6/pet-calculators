## 1. Launch checklist

Work top to bottom. Items marked **(gate)** must pass before you request indexing or apply to AdSense.

### 1.1 Configuration (all in `src/config/site.ts`, never hard-code these elsewhere)

- [ ] `siteUrl` is the final canonical origin, with `https://` and the chosen host (apex or `www`), no trailing slash. **(gate)** Currently `https://www.petcalctools.example`. Everything (canonicals, `og:url`, JSON-LD, sitemap, `robots.txt`) derives from it.
- [x] `contactEmail` is a real, monitored mailbox. **(gate)** Default `hammadiqbal117@gmail.com` (override with `PUBLIC_CONTACT_EMAIL`). The Contact page, footer, privacy/terms, and Organization schema use it.
- [ ] `defaultAuthor` and `reviewerPlaceholder` are replaced with real named people with real credentials, or the reviewer claim is removed. **(gate)** Never ship `[Veterinary reviewer name]`; `npm run audit:adsense` warns, and `AUDIT_PROD=1` fails the build.
- [ ] `buildDate` updated on every content release (drives `lastmod`, "Last updated" and `dateModified`).
- [x] `indexNowKey` set and matching `public/<key>.txt` (contents: the key) committed. Ping after deploy with `npm run indexnow` (section 3).
- [ ] `googleSiteVerification` and `bingSiteVerification` filled only if you verify with meta tags (DNS verification is preferred, see 2.1).
- [ ] `ga4MeasurementId` set (section 4) or deliberately empty.
- [ ] `adsensePublisherId` stays **empty** until AdSense approval ([ADSENSE.md](./ADSENSE.md)).
- [ ] `sameAs` lists only real profiles (GitHub, LinkedIn, X, YouTube...). Empty is better than fake.

### 1.2 Content and structure

- [ ] 8-15 working tools, each with >= 600 words of real explanation: answer-first paragraph, how to use, formula, worked example, assumptions/limits, FAQ, sources. **(gate)** Enforced by `audit:seo` (`thin-tool`).
- [ ] 3-5 guides, each >= 800 words with original examples/tables and cited veterinary sources. **(gate)**
- [ ] About, Contact, Privacy, Terms, Methodology pages exist and are linked from the footer. **(gate)**
- [ ] Custom 404 (`src/pages/404.astro`), `noindex`, no ads.
- [ ] Hubs `/tools/`, `/dogs/`, `/cats/`, `/guides/` have a unique intro (>= 150 words) and link to every child.
- [ ] Every page appears in [KEYWORD-MAP.md](./KEYWORD-MAP.md) with a unique primary keyword. **(gate)** Enforced by `audit:seo` (`keyword-map`, `cannibalization`).
- [ ] No orphans, no broken links (`npm run check:links`). **(gate)**
- [ ] Veterinary disclaimer on every tool and guide (`<Disclaimer />`); `ReviewerBox` only with a real reviewer ([`.cursor/rules/ymyl-disclaimers.mdc`](../.cursor/rules/ymyl-disclaimers.mdc)).

### 1.3 Technical

- [ ] HTTPS on the production host; one canonical host with 301 redirects from the other ([DEPLOYMENT.md](./DEPLOYMENT.md)).
- [ ] `robots.txt` (generated by `src/pages/robots.txt.ts`) allows Googlebot, Bingbot, OAI-SearchBot, PerplexityBot, Claude-SearchBot; does not block `/_astro/`; has `Sitemap: <siteUrl>/sitemap-index.xml`. **(gate)** Enforced by `audit:seo`.
- [ ] `sitemap-index.xml` and `sitemap-0.xml` generated by `@astrojs/sitemap`; `/embed/` and `/404` excluded (see `astro.config.mjs`); `lastmod` equals `buildDate` (update `buildDate` only on genuine content changes, per the playbook sitemap rules).
- [ ] Self-referencing absolute canonicals; trailing slashes everywhere (`trailingSlash: 'always'`).
- [ ] JSON-LD valid: `Organization` + `WebSite` (all pages), `BreadcrumbList` (non-home), `WebApplication` (tools), `Article` (guides). No `aggregateRating`/`review` unless real on-site ratings exist. FAQ markup is optional and gives no Google rich result (removed May 2026, SEO-PLAYBOOK section 2).
- [ ] Core Web Vitals pass on mobile: `npm run lhci` (Perf >= 95, LCP <= 2.5 s, CLS <= 0.1, TBT <= 200 ms) and PageSpeed Insights on 3 sample URLs.
- [ ] `og:image` is a **PNG/JPG/WebP** 1200x630 file. `BaseLayout.astro` currently points at `/og-default.svg`; Facebook, LinkedIn and X do not render SVG Open Graph images, so export a raster version into `public/` and update the layout (`audit:seo` warns `og-image-format`).
- [ ] Cloudflare/WAF is not blocking the AI search bots (check Bot Fight Mode and any "Block AI bots" toggle; DEPLOYMENT.md section 6).

### 1.4 Launch week

- [ ] Search Console: verify, submit sitemap, request indexing for `/`, the four hubs and the top 5 tools (section 2).
- [ ] Bing Webmaster Tools: import from Search Console, submit sitemap; IndexNow ping (section 3).
- [ ] 2-3 genuinely helpful community answers (section 8). One Show HN / Product Hunt style post only after the tools are polished.
- [ ] Record baseline: indexed pages, impressions, CWV field status, referring domains.

## 2. Google Search Console

1. Add a **Domain property** (DNS TXT verification, covers http/https/www/apex). With Cloudflare DNS this takes a single record ([DEPLOYMENT.md](./DEPLOYMENT.md)).
2. Sitemaps report: submit `sitemap-index.xml` (not only `sitemap-0.xml`). Expect "Success" and the discovered page count to equal the number of lines in the `audit:seo` info line "sitemap lists N URLs".
3. URL Inspection, "Request indexing" for: `/`, `/tools/`, `/dogs/`, `/cats/`, `/guides/`, then the 5 flagship tools (`puppy-weight-calculator`, `dog-food-calculator`, `puppy-food-calculator`, `dog-age-calculator`, `cat-age-calculator`). Use "View crawled page" to confirm the calculator HTML, H1 and FAQ are in the rendered output (they should already be in the initial HTML).
4. Indexing > Pages: every non-indexed URL must have an expected reason (embeds, 404). Anything "Crawled, currently not indexed" on a tool page is a content-quality signal: improve the page (examples, data, sources), do not resubmit.
5. Settings > Crawl stats: confirm 200 responses and no soft 404s.
6. Experience > Core Web Vitals and Page Experience: treat field data (CrUX) as the source of truth after about 28 days of traffic; lab data (`lhci`) is the pre-merge gate.
7. Performance > Search results weekly (section 10). In the Generative AI performance report (where available) note which tools and guides are cited.
8. Remove the temporary `pages.dev` hostname from the index if it ever got indexed (Removals tool) and keep `X-Robots-Tag: noindex` on it ([DEPLOYMENT.md](./DEPLOYMENT.md)).

## 3. Bing Webmaster Tools and IndexNow

- Verify at Bing Webmaster Tools by importing the Search Console property (fastest), then submit `sitemap-index.xml`.
- **IndexNow** reaches Bing, Yandex, Seznam, Naver, Yep and others; **Google does not participate** (SEO-PLAYBOOK section 2). Bing's index feeds several AI assistants, so keep it current.
- Key: `indexNowKey` in `src/config/site.ts` and `public/<key>.txt` (contents: exactly the key). Keys are public by design.
- **Post-deploy ping** (do not run inside `npm run build` — the key file must already be live):

```bash
# After a successful deploy of dist/ (includes /<key>.txt):
npm run indexnow
# or: node scripts/indexnow.mjs
# Dry-run (no POST): node scripts/indexnow.mjs --dry-run
```

  `scripts/indexnow.mjs` reads `dist/sitemap-index.xml` (and child sitemaps), POSTs every `<loc>` in batches of up to 10,000 to `https://api.indexnow.org/indexnow`, and logs the HTTP status. It always exits 0 so a ping failure never breaks deploy. Env: `PUBLIC_SITE_URL` (host / `keyLocation`), optional `INDEXNOW_KEY` override, `INDEXNOW_DISABLE=1` to skip. Workers Builds deploy command: `npx wrangler deploy && node scripts/indexnow.mjs` (same as `npm run deploy:indexnow`).

## 4. GA4 (analytics)

- Set `ga4MeasurementId` (`G-XXXXXXXXXX`) in `src/config/site.ts`; `BaseLayout.astro` injects gtag only when it is non-empty. The tag adds third-party JS, so re-run `npm run audit:budgets` (third-party scripts are allow-listed, not counted) and `npm run lhci` with the ID set before merging.
- Consent: the current cookie banner is informational only. Before enabling ads or serving EEA/UK traffic, put a certified CMP in front of gtag and enable Consent Mode ([ADSENSE.md](./ADSENSE.md) section 5).
- Link GA4 with Search Console (Admin > Product links).
- Events worth adding later (keep inputs out of events; calculator inputs stay in the browser and the privacy policy should say so): `calculator_used` (tool slug only), `result_copied`, `embed_click`, `outbound_click` (sources). Do **not** send weight, breed or any pet details.
- Track AI referrals: GA4 > Reports > Acquisition > Traffic acquisition, filter source contains `chatgpt.com`, `perplexity`, `copilot`, `gemini`, `claude`.
- Mark `calculator_used` as a key event only after it has real volume.

## 5. Keyword workflow

Full method is in SEO-PLAYBOOK section 1 and the [`keyword-research` skill](../.cursor/skills/keyword-research/SKILL.md). Condensed:

1. **Seed** with patterns: `[pet thing] calculator`, `how much [food/water] for a [dog/cat/puppy]`, `[pet] age in human years`, `[breed] weight at [age]`, `can dogs eat [food]`.
2. **Expand** with Google Autocomplete (`seed`, `seed + for`, `seed + a..z`, `seed + by breed/weight/age`). Record **distinct needs**, not phrasings.
3. **Mine questions** from People Also Ask (manual), r/puppy101, r/dogs, r/cats, r/AskVet threads and autocomplete "how/what/can/is" prefixes. These become FAQ items and guide outlines.
4. **Numbers**: Ahrefs free keyword generator / KD checker (manual, captcha-gated), Semrush free (10 lookups/day), Google Keyword Planner (CPC and ranges), then Search Console after launch. Record source and date next to every figure.
5. **Judge the SERP by hand** (incognito, US): >= 2 small/new sites in the top 10, tool pages (not long articles) ranking, KD <= 30 where known, outdated competitors, and no veterinary school / government pages holding three or more slots.
6. **Claim the keyword** in [KEYWORD-MAP.md](./KEYWORD-MAP.md) before writing. If it is a phrasing of an existing page, it is a secondary keyword of that page, not a new page.
7. **After launch**: GSC > Performance > Pages > a page > Queries; positions 8-30 with impressions are the next FAQ items, sections or articles.

## 8. Link building (see SEO-PLAYBOOK section 5)

Rules: no paid links without `rel="sponsored"`, no exchanges, no widget keyword links, no directory spam. Links come from usefulness. Use the `link-builder-researcher` subagent to build target lists.

1. **Resource pages.** Search `puppy "resources" "calculators"`, `new puppy checklist useful links`, `dog owner resources`, breed-club "puppy owner" pages, rescue/shelter "adopter resources" pages, pet-sitter and dog-walker blogs. Pitch the **specific** tool that fills a gap on the page (for example the puppy weight calculator for a "how big will my puppy get" section). Keep a sheet: URL, DR/DA, topic, contact, pitched date, outcome.
2. **Veterinary and breed communities.** Answer the actual question first in r/puppy101, r/dogs, r/cats, r/DogAdvice and breed forums; link only where rules allow and only when the tool is the answer. Never post inputs of "your" pet that were not real.
3. **Embeds.** The two embed pages (`/embed/dog-food-calculator/`, `/embed/puppy-weight-calculator/`; excluded from the sitemap; built from `EmbedDogFood.astro` and `EmbedPuppyWeight.astro` via `EmbedFrame.astro`) are the link asset. The embed snippet must include a plain, honest attribution link to the full calculator (no keyword-stuffed anchor text) and be offered to bloggers, groomers, trainers and shelters.
4. **Data stories.** The calculators run entirely in the browser and the privacy policy should say inputs are not collected. A data story therefore needs one of: (a) published datasets that you analyse and cite (for example breed weight ranges from `src/data/breeds.ts` compared against published breed standards), or (b) an explicit, opt-in aggregate analytics program announced in the privacy policy first. Never publish figures you cannot trace to a source.
5. **Journalist-request platforms.** Respond only with real expertise (your credentialed reviewer, if you have one). Platform availability was not verified in the research; check current options.
6. **Partnerships.** Offer the embed (and a free custom-branded version if justified) to pet-insurance comparison blogs, trainers, and local vets, with disclosure if there is any commercial relationship.
7. **Launch posts.** Product Hunt / Show HN once; indie directories that are curated (not "bookmark" farms).
8. **Reclaim mentions.** Search for the brand and tool names monthly; ask for links where the tool is named but not linked.

Measure real referring domains only (Meyerhans found raw counts can be about two-thirds spam). Target: 30 relevant outreach pitches in weeks 3-4, 50 more in weeks 7-8 (SEO-PLAYBOOK section 8).

## 9. Generative engine optimization (GEO / AI answers)

Google's stance (SEO-PLAYBOOK section 4): optimizing for AI search is still SEO. There is no special markup, and llms.txt is ignored by Google Search (and 97% of published llms.txt files get zero requests in Ahrefs' study). So:

- **Crawl access**: allow OAI-SearchBot, PerplexityBot, Claude-SearchBot and Googlebot. GPTBot, ClaudeBot, Google-Extended (training) are a separate choice; the repo default is allow. Verify the CDN is not blocking them (DEPLOYMENT.md section 6).
- **Answer-first writing**: every tool/guide starts (class `answer-first`) with a one to two sentence direct answer containing the formula or number, then a worked example with concrete values, then dated tables with sources. This is the content AI answers quote.
- **Be the calculator, not the description**: AI Overviews can describe a calculation but cannot hand over the working tool. Keep the tool above the fold and server-rendered, without sign-up.
- **Entity signals**: one brand name everywhere; `Organization` + `sameAs`; a real About page with named people; consistent author and reviewer boxes. No inauthentic mentions.
- **Freshness and provenance**: visible "Last updated", dated sources, a methodology page that names formulas and references. Re-verify at least every 6 months.
- **Do not**: rewrite pages into "chunks", add instruction-style text for bots, or publish llms.txt as a ranking tactic. If you add llms.txt anyway, keep it plain links.
- **Monitor** monthly with the [`ai-seo-geo-audit` skill](../.cursor/skills/ai-seo-geo-audit/SKILL.md): run 20 prompts (for example "how big will my labrador puppy get", "how many calories should a 20 kg dog eat", "dog age in human years by size") in Google AI Mode, ChatGPT search, Perplexity and Bing Copilot; record whether the site is cited, for which URL, and what the answer got wrong. Pair with GSC's Generative AI report and GA4 AI-referral traffic.
